<h2>Source files</h2>
<p>The app shell is assembled from <code>app/partials/*.html</code> into <code>app/public/index.html</code> (generated; never edit directly). Alpine components live in <code>app/client/</code> and ship as <code>/client.js</code>. Shared tokens and component styles are in <code>app/public/style.css</code>; the shell partials also carry effective style overrides. <code>app/public/theme.js</code> applies the appearance preference before CSS and first paint.</p>
<p>Examples and tables on this page are hand-written. The page links <code>/style.css</code>, so previews pick up real style changes, but its prose and markup stay as written. Edit this page when a component changes.</p>
<h2>Appearance</h2>
<p>Settings → Appearance offers System, Light, and Dark. System is the default and follows the device preference live; an explicit choice overrides it. The choice saves to your account and follows you across devices on their next load. <code>localStorage</code> under <code>slirc-theme</code> supplies the first paint and signed-out pages; after sign-in, the account preference takes over. Changes apply immediately. Failed saves keep the local choice without an error dialog. Blocked storage still allows changes on the current page. Invalid or missing preferences use System.</p>
<p><code>theme.js</code> sets <code>data-theme</code> and <code>data-theme-preference</code> on <code>&lt;html&gt;</code>, native <code>color-scheme</code>, and the browser theme color before the stylesheet loads. Theme selection must not wait for sign-in or Alpine.</p>

<h2>Typography, spacing, and layout</h2>
<p>New and edited components use the shared tokens in <code>app/public/style.css</code> instead of literal values; existing components migrate when touched. A literal needs a concrete layout or accessibility reason.</p>
<h3>Fonts</h3>
<p>Slirc loads no webfont, so JetBrains Mono shows only where it is installed. On desktop, nicks switch to the system font.</p>

<p>Line height is 1.45 for UI body and about 1.55 for messages. Conversation intros (<code>channel-intro</code>, such as the top of Notes or a new channel) sit in the message column but use <code>--ui</code>.</p>

<h3>Layout</h3>
<p>Desktop has a far-left workspace rail (when signed in with saved workspaces), a 15rem conversation rail, and an 860px maximum message column. Channels in the sidebar support desktop drag-to-reorder with a 30% opacity floating ghost row, plus Alt+Up/Down keyboard reordering. Phone layout checks for a coarse pointer as well as the width. Header height is <code>calc(3.625rem + env(safe-area-inset-top, 0px))</code>. Phone navigation is <code>--nav-h: 3.75rem</code>, lifted by <code>--nav-lift</code> (the home-indicator inset less .75rem, at least .5rem), and phone screens pad their bottom by both so content clears the tab bar. <code>--composer-space</code> is measured at runtime by <code>app/client/composer-editor.ts</code>, with CSS fallbacks before measurement.</p>

<h2>Glass, layering, and motion</h2>
<p><code>--blur-light</code> is blur(3px), <code>--blur-medium</code> blur(9px), <code>--blur-heavy</code> blur(18px). Glass pairs blur with a panel tint for text contrast. Floating glass surfaces share one tint, <code>--glass-tint</code> (panel at 74%), and <code>--glass-filter</code>. In dark the filter blurs and darkens what is behind (<code>saturate(1.2) brightness(.75)</code>) so a panel always sits below the content it covers; light only blurs and uses quieter shadows. Fixed chrome (header, docked rooms rail, members panel, composer, mobile nav) shares <code>--glass-chrome</code> (panel at 60%); dialogs stay near-solid at 96%.</p>
<p>An element with a <code>backdrop-filter</code>, or with a filter or opacity below 1, is a backdrop root. A blurred child inside it blurs nothing and the content behind shows through sharp. So a glass menu that opens from a blurred surface renders outside it. The composer + menu (<code>composer-plus-menu</code>) is teleported to the end of <code>body</code> with <code>x-teleport</code> and fixed at <code>--z-floating</code>. <code>placePlusMenu</code> in <code>app/client/popups.ts</code> sets its left edge on the + button and its bottom just above the composer, and places it again on resize and when the phone keyboard moves the composer. When blur fails to reach the content behind a panel, look for a backdrop root among its ancestors.</p>
<p>The overlay ladder lives in a second <code>:root</code> block: content 1, header 20, navigation menus 90/91, dialog 100, boot screen 102, <code>--z-tooltip</code> 120. Native dialogs use the browser top layer.</p>
<p>Motion tokens are under Typography, spacing, and layout. Component durations: <code>--dur-boot-exit</code> 150ms, <code>--dur-reaction</code> 380ms; dialogs use <code>--dur-fast</code>. The boot mark never animates: the iOS launch screen, the shell's Opening view and the boot screen draw it at the same size and place, and the boot screen fades out once as a whole. Inside the iOS shell the native overlay owns the mark and the page skips its boot screen. Reaction animations play once. Reduced motion removes nonessential entrances and transitions. Shared CSS still carries view-transition and arrival rules that the current shell disables. Document what the shell does and leave the dormant rules out.</p>

<h3>Tooltips and toast</h3>
<div class="ds-example"><span class="reaction-tooltip"><strong>👍<span>3</span></strong><small>Ada, Ben, and you</small></span><div class="glass-toast" role="status"><span>Channel link copied</span><button type="button" class="notify-banner-close" aria-label="Dismiss notification" data-dismiss-toast><svg viewBox="0 0 24 24" aria-hidden="true"><use href="/icons/lucide/sprite.svg#x"></use></svg></button></div><div class="glass-toast sticky" role="status"><svg class="toast-icon" viewBox="0 0 24 24" aria-hidden="true"><use href="/icons/lucide/sprite.svg#bell"></use></svg><span>Reminder: stretch</span><button type="button" class="toast-action">Open</button><button type="button" class="toast-action quiet" data-dismiss-toast>Dismiss</button></div></div>
<p class="ds-source">Generic <code>slirc-tooltip</code> lives in the shell partial and opens on hover and keyboard focus. <code>reaction-tooltip</code> and <code>thread-tooltip</code> remain separate variants. The shared tooltip uses a low-alpha panel tint for text contrast.</p>
<p class="ds-source"><code>glass-toast</code> pills sit above the composer in <code>toast-region</code> and come in two kinds.</p>
<p class="ds-source"><strong>Auto</strong> (the default, <code>note</code>) confirms something that just happened, or answers a command or input the app could not take; it shows even while the banner is up. A lighter layer drains toward the dismiss button over 5s, plus 1s per 30 characters of text up to 9s, and the toast closes when it empties; hover or keyboard focus pauses it. With reduced motion the layer stays still and the toast still closes on time. A newer auto toast replaces the current one.</p>
<p class="ds-source"><strong>Sticky</strong> (<code>glass-toast sticky</code>, <code>sticky</code>) is for something that needs the person, like a reminder that fired while they were elsewhere. It has no timer. It uses the same glass as other toasts, with a bell, a <code>toast-action</code> button and a quiet <strong>Dismiss</strong>, and it stays until one is chosen. It fades in once over 160ms, without movement under reduced motion, and never flashes. Its state is separate, so an auto toast never replaces or pushes it away; when both show, sticky sits above auto. Several sticky toasts stack newest first, up to three; after that one row says how many more wait, with <strong>Open</strong> and <strong>Dismiss all</strong>. <strong>Open</strong> goes to the conversation and clears every toast for it. Toasts live in the app shell, so they show on every screen: above the composer in a conversation, at the bottom of the screen (above the phone nav) elsewhere.</p>

<p class="ds-source"><code>mobile-nav</code> is the glass pill fixed low on phone screens, inside the home-indicator inset the way iOS tab bars sit. It holds Home, DMs, and More, with <code>nav-dot</code> for unread. The pill is <code>--nav-surface</code> (<code>--panel-hi</code> at 28% in dark, white at 45% in light) under a light blur, with no border. The <code>active</code> tab gets a <code>--nav-active</code> pill a small step lighter than the bar and a white label; the other tabs sit at 60%. It shows on the tab screens and the pages under More, and hides inside conversations and while the keyboard is open. <code>new-below</code> floats above the composer when new messages arrive out of view; tap to jump down. Both are fixed in the app and shown in flow here.</p>
<p class="ds-source">The More tab stacks three <code>more-card</code> groups (<code>--panel-hi</code> at 55%, <code>--radius-lg</code>) at the bottom, near the tab bar. The first is <code>more-profile-row</code>, with your photo in <code>more-avatar</code>, your account and the caption Profile, devices, sign out. The second holds the workspace switcher, Invitations, Agents, Admin for admins, and Get the iPhone app when offered. The workspace row ends with <code>workspace-count</code>, a <code>--panel-hi</code> pill with the number of saved workspaces in <code>--text-2xs</code> tabular digits. It hides when only one is saved, and the row's label reads the count to screen readers. The third card is Help &amp; docs, with the build as its caption. The floating profile photo hides on More, since the first card replaces it. On phone, Profile ends with a <code>more-card</code> of Devices, IRC clients, and Sign out, the last as a <code>mobile-row danger</code> in danger ink.</p>
<p class="ds-source">Pages opened from More or Profile sit at the bottom of the screen, just above the tab bar. <code>.profile-screen &gt; .mobile-screen-body::before</code> is a flexible spacer, so a short page drops to thumb reach and a long one scrolls from the top. Do not add a <code>mobile-spacer</code> to these pages. Tab screens keep <code>mobile-spacer</code>.</p>
<p class="ds-source">Phone screens scroll up and down only. <code>.mobile-screen-body</code> and <code>.mobile-settings-body</code> clip sideways overflow and stop the sideways rubber band (<code>overflow-x: clip</code>, <code>overscroll-behavior-x: none</code>), and on phones <code>.chat</code> and <code>.reply-thread-stream</code> do the same. Code blocks and tables that need the width scroll inside themselves. Anything wider than the screen is cut off rather than scrollable, so keep controls within their container. A hidden file input in a card takes <code>sr-only</code>, which the card's full-width input rule skips.</p>
<p class="ds-source">On phone Home, DMs, More and in a conversation, pulling down from the very top shows <code>pull-indicator</code> (<code>app/client/pull-refresh.ts</code>), a glass chip under the header that holds <code>pull-logo</code>. The logo follows the finger with resistance, grows and turns as it goes, and stays grey until the pull goes past 64px, where it takes its color. A release past that point checks the connection and loads newer messages for the open conversation, with no page reload. The logo breathes while that runs, pops once when caught up and leaves with no text. Offline or unreachable widens the chip with <code>pull-label</code>: You're offline, or Couldn't reach Slirc. Reduced motion only fades. A pull that starts below the top, within 24px of either screen edge, or while a composer has focus stays a scroll, a back swipe or a keyboard drag. The chip sits at <code>--z-pull-indicator</code> (27).</p>
<p class="ds-source">On phone, dragging down 24px or tapping the channel list or an open reply thread puts the keyboard away, but only while a composer has focus; taps on controls do nothing. In the iOS app and the Home Screen app, a swipe from the left 20px edge presses the back arrow on screen (<code>reply-thread-back</code>, then <code>profile-back</code>, then <code>header .mobile-back</code>). The page follows the finger and the swipe commits past 35% of the width or on a quick flick; reduced motion skips the slide. A screen with no back arrow ignores it, and text fields, open dialogs, sheets and sideways-scrolled code keep their own touches. A new phone screen with a back arrow uses one of those classes so the swipe finds it.</p>
<p class="ds-source">Docs opened from the iOS app or a phone show <code>app-back</code>, a sticky Slirc bar above the docs top bar, which takes the notch inset and returns to the app. Its height is <code>--app-back-h</code> (2.5rem), set by <code>docs-in-app</code>; the docs top bar, sidebar and heading scroll offsets add it. On screens up to 640px the docs page clips sideways too, and inline code outside <code>pre</code> wraps anywhere, while code in tables stays on one line.</p>
<p class="ds-source">The iOS app starts on its own workspace picker, <code>native/www/index.html</code>, with the same tokens. While it checks and opens a saved workspace, it shows <code>opening</code>: the slirc.org lockup pulsing at its center above Opening &lt;host&gt;…, with the pulse off under reduced motion. A workspace gets 5s to answer and 5s more for its client to start. A miss or a failed load brings back the picker with that workspace's card as <code>card failed</code> (a danger border at 55%) and a <code>tag failed</code> Couldn't reach pill where Current would be. A full-width Try again button sits above the form, and the field stays unfocused so the keyboard doesn't cover it. A cancelled load never opens the picker.</p>
<h2>Accessibility</h2>
<ul><li>Check text contrast against rendered backgrounds, including glass. Faint borders cannot be the only way to identify a control or keyboard focus.</li><li>Label icon-only controls.</li><li>Show keyboard focus with a solid accent outline.</li><li>Dialogs keep Tab within visible, enabled controls. Escape cancels; closing returns focus to the opener.</li><li>Preserve focus and text selection during rerenders.</li><li>Keep fixed phone controls clear of safe-area insets.</li><li>Use shortcode alt text for custom emoji. Show important state with text, icon, count, or position, not color alone.</li><li>Honor reduced motion. Allow text selection when a mouse or other fine pointer is available.</li></ul>
